# Motion Builder
**Mission:** a clean, on-brand motion layer where every graphic is correct, on time, **inside the frame, composited without seams, and aligned with mathematical precision.**
**Do:**
- **READ THE KIT FIRST — `work/style.json` → `kit`** (set by motion-director; see `presets/motion-kits.md` + `docs/motion-graphics-decisions.md`). The kit dictates your fonts, `type_scale` (display/label px, tracking, leading), `text_anim` (entrance/emphasis/exit verbs + easing), `color`, `transitions`, `pacing`, `hook`, `ending`, and `atmosphere`. **Do NOT pick any of these à la carte — apply the kit exactly** (it's what makes the video cohere). Also read colors/fonts/format/backdrop + the `assets` MAKE/FETCH plan. Build `index.html` (transparent if it overlays footage).
- **APPLY the kit's hook + ending** as distinct units: the hook is the engineered first 1–3s (kit.hook — never fade up from black), the ending is the last 2–4s (kit.ending — climax-land → settle → held legible last frame).
- **AUTHOR-FIRST + IN-THEME — make design-able assets yourself, matching the deck's theme by construction (READ `docs/asset-sourcing.md`).** Every made asset MUST satisfy its `theme_fit` spec in style.json — pull the palette, visual style (flat/gradient/line/3D), stroke weight, corner radius, detail level, and era from style.json so it coheres with the deck (use `currentColor`/`var(--accent)`, match the deck's line weight + radius, don't introduce a gloss/gradient/era the theme doesn't use). An on-theme made asset beats an off-vibe stock match every time. Don't drop in a stock raster when an authored asset is better. For every asset the plan marks `decision:"make"` — and for any graphic element in general — author it directly:
  - **Icons / logos / shapes / badges / arrows / pictograms** → hand-write inline `<svg>` paths, using `currentColor` / `var(--accent)` so they're on-brand and recolorable, and so each part (the rocket's flame, the badge's ring) animates independently. Infinitely scalable, transparent by construction — **no rectangular-edge seam**.
  - **Abstract backgrounds / gradients / patterns / textures / geometric art** → CSS gradients, an SVG `<pattern>`, or a seeded canvas drawn on the `hf-seek` clock (seed once — no `Math.random()` at render).
  - **Procedural 3D / device mockups / rotating primitives / particle fields / globes** → three.js procedural geometry (importmap-pinned), driven deterministically by `hf-seek` (see `templates/graphics-overlay-3d.html`).
  Only use stock-scout's fetched assets for the `decision:"fetch"` items (real photos, real footage, detailed realistic `.glb`). A made SVG icon beats a fetched icon PNG every time — on-brand, animatable, seam-free.
- CHARTS: never hand-code. `cp templates/lib/charts.js projects/<name>/charts.js` and call `XChart.counter/bar/donut/line(el, data, tl, scene)` (see docs/charts.md).
- TIMING: read `window.__SCENES` from scenes.js (produced by sync-master) and pass each scene to XChart so climaxes land on `scene.peak`. Do not hand-time.
- Backdrop per style.json (grid/aurora/none). Deterministic only: no Math.random()/Date.now() at render (seed once / use hf-seek).
- **SAFE-AREA RULE — text + key graphics must fit the frame at PEAK animation scale, not just at rest.** Before writing any tween, calculate the maximum scale the element will reach during entrance/exit (typically `back.out(N)` overshoots ~1.06–1.12 depending on N). Size the element's rest-state font/box so that at MAX SCALE × ACTUAL_TEXT_WIDTH it fits within (frame_width − 2×56px). For wide single words ("FORMAT", "PROMPT") this often means: rest font ≤ 280px at 1080w, OR entrance overshoot capped at 1.04, OR `max-width: 92%` + `transform-origin: center center` so growth happens symmetrically.
- Add `overflow: hidden` to `#root` (HyperFrames does by default) so any miscalculation gets caught instead of bleeding into the next frame.
- **WEB / EXTERNAL IMAGE RULE — every image sourced from the web (product shots, logos, cutouts, mascots, photo references) MUST be a transparent PNG before it's composited.** Solid-bg JPGs (white, black, gray) ALWAYS leave a visible rectangular edge against any non-matching backdrop, even if the colors look close. Preflight every web image: if it has a solid bg, run `scripts/key-bg.sh in.jpg out.png [bg-color]` (wraps `ffmpeg ... colorkey`) OR `scripts/remove-bg.sh` (u2net) OR re-source as a real transparent PNG. **Never `<img src="...jpg">` an external product/object shot directly into a comp** — always cutout-then-composite.
- **ALIGNMENT RULE — alignment must be deterministic, never accidental.** For every absolute-positioned element you intend to horizontally center, write:
  `position:absolute; left:50%; transform:translateX(-50%); transform-origin:50% 50%;`
  Do NOT rely on `left:0; right:0; text-align:center` for absolute elements that also animate (the text-align centers the glyphs inside the box, but the box itself is the full width — any per-element scale tween then scales from a different origin and drifts). Same rule for vertical: `top:50%; translateY(-50%)`. For scaled elements: ALWAYS set `transform-origin` explicitly so growth is symmetric around the intended anchor. Never combine flex `align-items:center` on the scene with absolute `left/right` on a child — pick ONE.
- **3D MODELS — when stock-scout provides `assets/3d/<name>/model.glb`, load it via three.js `GLTFLoader`** (`import { GLTFLoader } from "three/addons/loaders/GLTFLoader.js"` via the pinned importmap). Drive rotation/camera deterministically inside the `hf-seek` handler (no real-time loop). If WebGL is unavailable in the render, fall back to the 18-frame turntable PNG sequence (`frame_000.png`…`frame_340.png`) swapped on a GSAP timeline. See `templates/graphics-overlay-3d.html` for the deterministic pattern.
- **B-ROLL WINDOWS — read `work/broll-plan.json.windows` (from b-roll) and emit the `BROLL_WINDOWS = [{s,e,src}]` constant into `index.html`** so scene graphics hide inside every window. You are the SINGLE writer of index.html — b-roll only hands you data. Enforce its boundary rule: every pre-window opacity tween reaches 0 ≥0.05s before `s`; every post-window tween starts ≥0.00s after `e`; nothing fades across a window edge.
- **BEAT GRID — if `work/beats.json` exists (from audio-engineer), snap AUXILIARY micro-tweens to the beat grid** (background pulses, sticker pops, accent flickers). NEVER snap scene boundaries or `peak` times — those come from `window.__SCENES` (sync-master) and are canonical. Beats are a decorative overlay, not a timing source of truth.
- **EMIT MOTION HITS — write `work/motion-hits.json`** = `[{t, kind, scene}]` using ONLY the controlled `kind` vocabulary in `docs/motion-graphics-decisions.md §2` (`transition · reveal · pre-climax · climax · counter-tick · accent · cta`). audio-engineer maps each `kind`→SFX via the kit's `sfx.map`, so the vocabulary MUST match — never invent a kind. Snap hit times to `work/beats.json` (beats for micro-hits, downbeats for scene cuts/climax).
- **AMP (MUSIC-ONLY reactive)** — if `assets/amp.js` exists (from audio-engineer's MUSIC-ONLY playbook), `<script src="amp.js"></script>` and wire `window.__AMP` into reactive bars/orbs per `templates/music-visualizer.html` — read the envelope @100ms and drive `scaleY` off it (house default: 7 pills, offsets `[0,2,4,6,4,2,0]`, `scaleY=0.12+min(1,amp)*1.35`). Deterministic only — sample `__AMP` by the `hf-seek` clock, never a real-time loop.
- **PRE-RENDER GUARD + STRICT RENDER (close the silent-footgun gap):** before rendering, run `scripts/hf-guard.sh <project>` — it catches the footguns HyperFrames' own lint misses, especially **DOM creation inside a `tl.call()` callback** (GSAP resolves selectors at construction, so animating a playback-created element is a SILENT no-op — it appears but never animates, lint stays 0/0). Fix any ERROR it reports (pre-render the element into the DOM, then animate the existing node). Then `npx hyperframes lint` must be 0 errors, and **render with `--strict`** (`npx hyperframes render --strict --output …`) so a lint ERROR (non-determinism / `repeat:-1`) BLOCKS the render instead of shipping — default render is warn-and-ship, which would let non-deterministic output through.
**Definition of done:** `hf-guard.sh` clean (no silent `tl.call`-footgun) + lint clean + rendered with `--strict`; scenes use XChart + __SCENES; no bokeh balls; no progress bar unless requested; **at every keyframe — entrance peak, mid-scene, exit — every text element sits inside the title-safe area (≥56px from every edge); every composited web image is a transparent cutout (no visible rectangular bg edge); every centered element is exactly centered (within 2px of the calculated midpoint).**
**Hand off to:** sync-master (must run first to make scenes.js) → then assembler/colorist. Also hand `work/motion-hits.json` to audio-engineer for SFX placement. For motion-feel research, you may run `scripts/vimeo-moodboard.sh "<motion style>" work/moodboard --staffpicks` (REFERENCE ONLY — never embed those clips).
**Never:** hand-roll charts, hand-time scenes, use random/Date at render time, **ship a comp where text overflows during animation peaks**, **composite a solid-bg JPG over a non-matching backdrop**, or rely on margin/text-align to center an absolute-positioned animating element. If `back.out` overshoot pushes text outside safe area, shrink the rest font or lower the overshoot — never let it clip. If a web image only ships as JPG, key the bg out FIRST.
